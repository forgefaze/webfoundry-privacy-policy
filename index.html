01About this policy

This policy explains how the WebFoundry Capture Chrome extension (“the extension”, “we”, “us”) handles information when you use it. The extension has a single purpose: capturing a rendered web page as editable design data for the WebFoundry Importer plugin in Figma.

The extension only does something when you tell it to. Opening the popup, clicking Capture page or Select element, and saving the file are all your actions. It does not run in the background on the pages you browse.

02What the extension reads

When you start a capture, the extension reads the following from the one tab you are capturing, and only for as long as the capture takes:

InformationWhy it's needed
Layout and stylesPositions, sizes, colours, spacing, borders, effectsTo rebuild the page as Figma frames with Auto Layout, variables and text styles.
Visible textIncluding link text and image alt textTo create editable text layers that match the page.
Images, icons and fontsAs already loaded or referenced by the pageTo place images and vector icons and to identify the fonts actually rendered.
Images of canvas, video and embedded contentThese can't be rebuilt as layers, so they are captured as images.
Page title and addressAddress without any query stringTo name the Figma frame (for example “Pricing · 1440”) and record where the design came from.
Link destinationsWithout query stringsTo keep links clickable in Figma. Removed when redaction is on.
Form control statesOnly if you turn on “Include form control states”To show checked boxes, radio buttons and selected options as they appear.

If the page shows personal information, such as a logged-in account screen, it is part of what appears on the page, so it will be in the capture. The Redact digits and e-mails option replaces every digit with 0 and masks e-mail addresses in text, layer names, alt text and the page address, and removes links.

What redaction doesn't cover: names, or anything inside images, canvases, videos or embedded frames. Check the file before you share a capture of a customer screen.

03What it never captures

  • Passwords or other values typed into fields
  • Text area and editable-region contents
  • Dropdown values (unless you turn on form states)
  • Cookies, tokens or login credentials
  • The page's scripts or source code
  • Query strings in addresses and links
  • Other tabs, windows or your browsing history
  • Your clicks, scrolling or keystrokes
  • Your location or IP address
  • Any information about who you are

Placeholder text in empty fields is captured, because it is part of the design.

04Where your data goes

It stays on your computer. The extension packages the capture in your browser and saves it as a .wfd file to your Downloads folder, or to a location you choose if “Ask where to save” is on.

  • While the file is being saved, a temporary copy is held in the extension's private browser storage. It is deleted as soon as the file is handed to Chrome's download manager.
  • The extension does not send anything to WebFoundry or anyone else. It has no server, account system or analytics.
  • To include images, icons and fonts, the extension may request those files from the website you are capturing, the same way your browser loads them when you view the page, using your existing session with that site. These requests go only to that website and the services it already uses.
  • The WebFoundry Importer plugin for Figma is set to no network access. It reads the file you drop in and creates layers in your Figma document. Figma's own privacy policy covers your Figma files.

05Settings stored in Chrome

The extension remembers a few preferences in Chrome's local extension storage, on your device only:

  • Which viewports you selected and their widths
  • Image quality and capture options (hide overlays, redaction, form states, mobile user agent, ask where to save)
  • The current capture status and progress, shown in the popup
  • Whether you dismissed the “Get the Figma plugin” tip

No page content or personal information is kept in these settings, and they are not synced to your Google account.

06Permissions and why

  • activeTabLets the extension work only on the tab you are looking at, and lets the popup tell you when Chrome blocks a page from being captured.
  • debuggerChrome's DevTools Protocol is the only way to read a rendered page accurately enough to rebuild it in Figma, and to render it at the widths you pick. The extension attaches to that one tab when you click Capture and detaches as soon as it finishes or you cancel. Chrome shows a bar at the top of the tab while it is attached.
  • downloadsSaves the finished .wfd file to your computer.
  • storageRemembers your settings, as described above.
  • offscreenA technical helper that hands the finished file to Chrome's download manager. It has no interface and does nothing else.

07Sharing your captures

A .wfd file is yours, like any other file on your computer. It contains what was on the page when you captured it. If you send it to someone or import it into a shared Figma file, they can see that content. Use redaction and check the file before sharing captures of private or customer screens.

08Third parties and sale

  • We do not sell or transfer user data to third parties.
  • We do not use or transfer user data for any purpose unrelated to capturing pages for Figma.
  • We do not use or transfer user data to determine creditworthiness or for lending purposes.
  • We do not use data for advertising, and no person at WebFoundry can read your captures.

WebFoundry Capture's use of information complies with the Chrome Web Store User Data Policy, including the Limited Use requirements.

09Retention and deletion

We don't hold any of your data, so there is nothing for us to keep or delete. You are in control:

  • Captures: delete the .wfd files from your computer whenever you like.
  • Settings: removing the extension from chrome://extensions deletes all of its stored settings.
  • Figma imports: delete the layers or file in Figma.

10Children

WebFoundry is a professional design tool and is not directed at children. We do not knowingly process information about children.

11Changes to this policy

If a future version changes how data is handled, we will update this page and its effective date before that version is released. If a change ever involves data leaving your device, we will describe it here first and ask for your consent where required.
